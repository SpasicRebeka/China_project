# 医语桥患者端产品需求文档

> 版本：v0.1 第一轮评审稿  
> 日期：2026-07-27  
> 状态：需求讨论中  
> 产品定义：医生引导、患者单题作答的无声问诊触摸终端  
> 适用范围：成人听障患者，本地双 7 英寸触摸屏门诊研究原型

## 1. 文档目的

本文档定义患者端下一阶段的产品目标、核心流程、页面结构、触摸交互、异常处理、数据规则和 MVP 验收标准。

患者端不是医生端的缩小版。它只承担三个任务：

1. 清楚展示医生当前发送的问题。
2. 让患者通过触摸完成结构化回答。
3. 明确反馈回答是否已提交、医生是否已收到，以及当前是否需要继续等待。

## 2. 当前基线与已知问题

当前患者端已经具备：

- 简体中文、繁体中文和英文切换。
- 会话缺失、连接中、已连接和断开状态展示。
- 本地双端实时通道的基础能力。
- 无会话凭证时的安全等待页。

当前尚未具备：

- 医生问题接收与渲染。
- 结构化回答控件。
- 回答确认、修改、跳过和不确定状态。
- 单题问诊流程和问诊进度反馈。
- 断线时的草稿保留与恢复。
- 会话结束后的本地数据清除反馈。

2026-07-27 在 1024 x 600 视口实测发现：

- 页面文档高度为 695 px，固定屏幕出现纵向滚动。
- 语言选择控件高度为 42 px，不适合作为患者端主要触摸控件。
- 当前中心卡片最小高度为 430 px，加上 92 px 顶栏和页脚后无法完整落入一屏。
- 页面仍是通信验证空壳，不能完成实际问诊任务。
- kiosk 启动脚本和部署示例已经按双 1024 x 600 屏幕配置，患者页面仍需在这一固定视口内单独完成无滚动验收。
- 当前实时服务会向同一会话中的连接广播事件，尚未建立医生内部事件的服务端角色隔离。

## 3. 背景与核心问题

听障患者在面对口头问诊时，可能无法完整接收医生的问题，也可能因为医学术语、时间压力或表达方式不匹配而难以准确回答。

患者端需要把医生当前的问题转化为一个清楚、可触摸、可确认的单一任务。系统不得替患者解释症状，不得推断诊断，也不得用危险提示制造额外焦虑。

## 4. 产品目标

### 4.1 总目标

帮助成人听障患者在不依赖声音、鼠标或物理键盘的前提下，通过 7 英寸触摸屏理解并完成医生发送的结构化问诊问题。

### 4.2 一级目标

1. 看得懂：一屏只展示一个问题，使用患者可理解的文字和必要图形。
2. 点得准：所有关键操作具有足够大的触摸热区和清楚的选中状态。
3. 答得稳：提交前允许检查，提交后明确告知发送结果。
4. 不被迫猜：不确定、看不懂、无法表达和跳过是正式交互状态。
5. 不依赖听觉：所有状态变化均有文字、颜色和形状反馈。
6. 能从异常中恢复：短时断线不丢失当前未提交选择。

### 4.3 非目标

首版不提供：

- 自动诊断、疾病概率或治疗建议。
- 患者自行选择问诊路径或浏览知识图谱。
- 患者端危险信号结论或急诊去向建议。
- 自动手语识别、视频问诊或语音识别。
- 长期健康档案和跨次就诊记录。
- 面向儿童、急性精神危机、创伤或专病流程的独立适配。
- 患者端病历编辑和医生记录查看。

## 5. 用户与使用环境

### 5.1 核心用户

| 用户特征 | 主要需求 | 设计响应 |
| --- | --- | --- |
| 聋人或重度听力障碍患者 | 不依赖声音获取问题和反馈 | 全程文字与视觉状态反馈 |
| 轻中度听力障碍患者 | 减少重复口头沟通 | 单题大字展示和结构化选项 |
| 中文读写能力存在差异的患者 | 减少复杂医学表达 | 短句、通俗词、必要图形和求助入口 |
| 视力下降或精细动作能力较弱的成人 | 看清并准确点击 | 大字号、大热区、低密度布局 |

### 5.2 典型环境

- 医生和患者在同一诊室。
- 患者端运行在横屏 1024 x 600 的 7 英寸固定触摸屏。
- 浏览器使用全屏或 kiosk 模式，页面不依赖浏览器工具栏。
- 目标验收环境使用 1024 x 600 CSS 视口、100% 浏览器缩放；操作系统缩放和设备 DPR 必须在设备配置中冻结并记录。
- 核心流程不要求外部网络。
- 不假设存在鼠标、悬停状态、物理键盘或声音输出。
- 医生负责开始、发送问题、确认回答和结束会话。

## 6. 产品原则

1. 一屏一问：患者一次只处理一个明确任务。
2. 明确提交：选择答案不等于提交，避免误触后立即发送。
3. 状态保真：未回答、不确定、看不懂、跳过和已回答必须区分。
4. 患者可理解：患者端只展示问题和回答方式，不展示医学规则内部名称。
5. 医生主导：患者不能绕过医生主动进入下一题。
6. 无声优先：声音只能作为未来可选增强，不能承担唯一反馈。
7. 触摸优先：不以悬停、右键、双击、长按或复杂手势完成主流程。
8. 数据最小化：患者端不展示姓名、诊断、风险分层和完整病历。

## 7. 首版范围

### 7.1 主诉范围

首版与知识库 v0.1.0 和医生端一致，覆盖 7 个主诉：胸痛、胸闷、咳嗽、发热、腹痛、头晕和乏力。

患者端不直接展示主诉选择页。主诉由医生端选择，患者端只接收相应问题。

### 7.2 回答类型范围

知识库当前包含以下输入类型：

| 输入类型 | 当前知识库规模 | 患者端控件 |
| --- | ---: | --- |
| 单选 | 35 个问题 | 大按钮列表或 2 列网格 |
| 多选 | 17 个问题 | 可复选的大按钮网格，加“完成选择” |
| 时长 | 2 个问题 | 数字输入、单位选择和持续状态 |
| 数字 | 2 个问题 | 大号数字选择器或专用数字键盘 |
| 日期或相对时间 | 1 个问题 | 相对时间选择与日期选择器 |
| 自由文本 | 1 个问题 | 全屏文本输入，调用系统触摸键盘 |
| 身体部位图 | 由 value set 驱动 | 可触摸区域图，加文字回显 |

所有医学问题、选项、单位、条件和来源均来自版本化知识库。前端只能定义控件表现，不得在组件中另写一套医疗问题和答案。

当前知识库元数据支持简体中文和英文。现有界面虽然提供繁体中文入口，但繁体医学问题和选项尚未完成独立审校，不能把简繁自动转换视为医疗内容本地化完成。

## 8. 核心使用流程

### 8.1 主流程

```text
患者端打开
  -> 检查会话凭证
  -> 等待与医生端连接
  -> 显示“请等待医生发送问题”
  -> 接收一个问题
  -> 患者阅读并选择答案
  -> 患者点击“确认提交”
  -> 患者端显示发送成功
  -> 等待医生确认或发送下一题
  -> 医生发送下一题
  -> 重复单题作答
  -> 医生结束会话
  -> 患者端显示结束页并清除本地临时数据
```

### 8.2 会话状态

```text
无会话 -> 正在连接 -> 等待问题 -> 正在作答 -> 正在发送 -> 已提交
              |             |            |
              +---------- 连接中断，可恢复 ----------+

任意进行中状态 -> 医生结束会话 -> 已结束并清除
```

### 8.3 回答状态

- 未开始：问题已显示，尚未选择。
- 已选择：已有本地选择，尚未提交。
- 正在发送：防止重复点击。
- 已提交：患者不可直接覆盖本次提交。
- 发送失败：保留选择，可再次提交。
- 不确定：患者明确表示不能确定答案。
- 看不懂：患者请求医生解释或改写。
- 跳过：患者主动不回答本题。

## 9. 信息架构与 1024 x 600 布局

### 9.1 固定三段式布局

```text
┌──────────────────────────────────────────────────────────────┐
│ 64 px 顶栏：品牌 | 当前状态 | 语言                          │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│ 452 px 主任务区                                               │
│ 问题类型提示                                                  │
│ 当前问题                                                      │
│ 回答控件或选项                                                │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│ 84 px 操作栏：辅助操作 | 主提交按钮                           │
└──────────────────────────────────────────────────────────────┘
```

- 页面总高度固定为 600 px，主流程不得出现页面级纵向滚动。
- 页面水平内边距建议 24 px，最小安全边距 16 px。
- 顶栏只保留品牌、真实连接状态和语言入口，不展示技术事件名。
- 主操作栏固定在底部，但不得遮挡主任务区。
- 选项过多时使用显式分页，不使用细小滚动条，也不依赖滑动发现内容。

### 9.2 信息优先级

1. 当前问题。
2. 回答选项和选中状态。
3. 主操作按钮。
4. 连接、发送和等待状态。
5. 会话编号、隐私提示和语言设置。

### 9.3 顶栏规则

- 品牌区宽度控制在约 220 px 内。
- 中部显示一个真实状态：“正在连接”“等待医生”“请作答”“已提交”或“连接已断开”。
- 语言按钮最小高度 60 px，切换语言不能清空当前未提交选择。
- 会话编号仅显示短编号，可放入次级信息，不与问题争夺注意力。

## 10. 页面与状态需求

### 10.1 无会话页

- 标题：“等待问诊会话”。
- 说明患者需要使用医生端生成的链接进入。
- 不显示“重试”按钮，除非系统可以执行真实重试。
- 页面必须完整落入 1024 x 600，不出现滚动。

### 10.2 连接中页

- 明确显示“正在连接医生端”。
- 使用轻微、非声音的状态变化。
- 超过合理等待时间后显示“连接时间较长，请让医生检查设备”。
- 不显示 WebSocket、token 或事件类型等技术信息。

### 10.3 等待问题页

- 主标题：“已连接，请等待医生发送问题”。
- 显示当前语言和短会话编号。
- 不出现空白回答控件。
- 医生端发送问题后直接切换到作答页，不要求患者额外点击进入。

### 10.4 单题作答页

- 只显示一条问题。
- 问题文字最多占 3 行，超出时由内容治理解决，不通过缩小字号解决。
- 选项文案尽量保持一行，最多两行。
- 患者选择后必须有颜色、边框和图标三重反馈中的至少两种。
- 选择答案后主按钮从禁用变为可用。
- 不允许点击选项后自动提交。

### 10.5 已提交等待页

- 显示“回答已发送给医生”。
- 回显本次提交内容，允许患者确认自己发送了什么。
- 默认不提供直接修改按钮，避免与医生端确认状态冲突。
- 如需更正，患者可点击“我需要更正”，向医生端发送更正请求，由医生决定是否重发本题。

### 10.6 会话结束页

- 显示“本次问诊已结束”。
- 明确说明患者端临时回答已从本屏清除。
- 不展示病历草稿或风险结论。
- 页面停留在安全结束状态，直到新的带凭证链接打开。

## 11. 回答控件规范

### 11.1 单选

- 2 至 4 个选项优先使用单列大按钮。
- 选项较短且语义并列时可使用 2 列网格。
- 每个选项高度至少 64 px。
- 全卡片可点击，不只让文字区域可点击。
- 切换选择时更新本地状态，不立即发送。

### 11.2 多选

- 使用 2 列大按钮网格，避免小复选框。
- 选中项显示明确勾选图标和高对比边框。
- “都没有”“不确定”“跳过”如果由知识库提供，必须与普通症状选项建立互斥规则。
- 选项超过一屏容量时使用“上一组”“下一组”，并持续显示已选数量。
- 最终通过“完成选择”或“确认提交”发送。

### 11.3 数字和量表

- 严重程度量表直接使用知识库定义的范围和单位。
- 数字键或刻度热区至少 56 x 56 px。
- 当前值必须以大号数字和文字同时回显。
- 不依赖拖动细小滑块完成精确选择。

### 11.4 时长与相对时间

- 数值和单位分开选择，单位由知识库或数据字典提供。
- “持续存在”“记不清”等特殊状态使用独立大按钮。
- 日期选择器必须适配触摸屏，不直接依赖桌面浏览器的小型原生控件。

### 11.5 身体部位图

- 图形必须与文字列表联动。
- 可点击区域之间留有足够间隔，避免相邻部位误触。
- 选中后在图旁用文字回显已选部位。
- 身体图不是唯一入口，无法准确点图时可切换到文字选择。

### 11.6 自由文本

- P0 仅用于知识库明确要求的简短说明。
- 进入文本模式后采用全屏输入布局，减少系统触摸键盘遮挡。
- 始终提供“不方便输入”和“请医生协助记录”。
- 文本未提交时断线不得清空。

## 12. 触摸交互硬性规范

1. 主按钮高度至少 64 px。
2. 普通可触摸目标至少 60 x 60 px。
3. 相邻独立目标间距至少 10 px，危险或不可逆操作间距至少 16 px。
4. 常规正文不小于 18 px，选项文字建议 20 至 24 px，问题文字建议 30 至 36 px。
5. 所有触摸操作在 100 ms 内给出按下反馈。
6. 禁用状态不能只用降低透明度表达，必须同时给出不可用原因或保持明显差异。
7. 不使用 hover 承载信息。
8. 不要求双击、长按、拖拽或边缘滑动完成核心流程。
9. 主操作按钮位置在不同题型间保持稳定。
10. 任何一题在默认字号下均应在一屏完成，不能依靠页面级滚动。

## 13. 视觉与文案规范

### 13.1 视觉方向

- 可信、安静、直接，不使用娱乐化动效。
- 延续现有患者端暖棕色作为单一强调色，但提高正文和边框对比度。
- 卡片采用统一的 16 px 左右圆角体系，按钮采用同一圆角规则。
- 连接状态可以使用颜色，但必须同时有文字和形状，不只依赖红绿颜色。

### 13.2 文案规则

- 一句话只表达一个动作或问题。
- 避免疾病名称、风险分层和内部医学术语。
- 避免责备式文案，如“你还没有完成”。改为“请选择一个答案后提交”。
- 对不确定性使用中性表达，如“不确定”“记不清”“不方便回答”。
- 按钮使用动作词：“确认提交”“下一组”“请医生解释”“重新发送”。
- 患者端不显示“通信空壳”“最近事件”“token”等开发术语。

## 14. 功能需求

### 14.1 会话与连接

#### PT-S01 安全进入会话，P0

- 只有有效患者角色凭证可以进入问诊状态。
- 凭证缺失或错误时进入安全等待页，不泄露会话数据。

#### PT-S02 连接状态反馈，P0

- 状态至少包含连接中、等待问题、连接正常、连接断开和会话结束。
- 状态变化不依赖声音。

#### PT-S03 断线恢复，P0

- 断线时锁定提交按钮，但保留本题未提交选择。
- 重连成功后恢复当前问题和本地选择。
- 如果医生端已经结束会话，患者端进入结束页。

### 14.2 问题接收与展示

#### PT-Q01 单题接收，P0

- 同一时间只允许一个活动问题。
- 新问题必须包含问题 ID、题型、患者语言文案、回答约束和知识库版本。

#### PT-Q02 条件问题，P0

- 患者端只展示医生端实际发送的问题。
- 题目显示条件由知识库和医生端决定，患者端不自行推断下一题。

#### PT-Q03 通俗展示，P0

- 使用知识库患者文案，不展示字段名和内部编码。
- 文案无法在 3 行内展示时进入内容治理清单。

### 14.3 回答与提交

#### PT-A01 结构化选择，P0

- 支持单选、多选、数字、时长、相对时间、身体部位和简短文本。
- 控件根据 answer_type 和 value_set 渲染。

#### PT-A02 显式提交，P0

- 任何选项点击都只改变本地选择。
- 只有点击“确认提交”才发送回答。
- 发送中禁止重复提交。

#### PT-A03 回答回显，P0

- 提交成功后显示结构化值对应的患者可读文本。
- 不显示内部编码。

#### PT-A04 不确定与跳过，P0

- 不确定、看不懂和跳过使用不同状态值。
- “看不懂”必须通知医生端，而不是作为普通答案保存。

#### PT-A05 更正请求，P1

- 患者提交后可请求更正。
- 更正请求不直接覆盖已提交记录，由医生端决定是否重发。

### 14.4 语言与沟通辅助

#### PT-L01 语言切换，P0

- P0 支持经过审校的简体中文和英文。
- 繁体中文作为目标能力保留，但必须在医学问题和选项独立审校完成后开放。
- 切换语言不丢失当前选择。
- 当前问题必须有目标语言文案，缺失时使用明确的降级提示，不静默显示字段编码。

#### PT-L02 请求解释，P0

- 作答页提供“请医生解释”入口。
- 触发后患者端进入等待状态，医生端收到解释请求。
- 请求解释不等于跳过，也不提交空回答。

#### PT-L03 非声音反馈，P0

- 连接、选中、发送成功、发送失败和会话结束均有文字反馈。
- 未来如增加声音，必须提供关闭入口，并保留完整视觉反馈。

### 14.5 隐私与结束

#### PT-P01 最小展示，P0

- 患者端只显示短会话编号，不显示姓名、身份证号或医生记录。

#### PT-P02 会话清除，P0

- 医生结束会话后清除患者端内存中的题目、选择和回答回显。
- 结束页不得通过浏览器后退恢复已清除内容。

## 15. 关键业务规则

1. 医生端是问题发送和会话推进的唯一控制端。
2. 患者端一次只维护一个活动问题和一个未提交草稿。
3. 选项点击不自动提交。
4. 患者回答、患者跳过、患者不确定和请求解释必须使用不同事件类型。
5. 危险信号规则只在医生端计算和展示。
6. 患者端不得根据回答展示诊断、风险结论或处置建议。
7. 医生确认后的回答不能被患者端静默覆盖。
8. 所有问题和选项必须携带知识库版本，便于追溯。
9. 断线恢复后以服务端活动问题为准；若本地草稿对应同一问题，则恢复草稿。
10. 会话结束后本地临时数据必须不可恢复。
11. 医生内部备注、危险信号、规则条件和医生修订必须在服务端按目标角色路由，不能只依赖患者前端不渲染。
12. 患者角色只能发送协议白名单中的回答、解释请求、更正请求和语言事件，不能发送任意事件类型或载荷。

## 16. 数据需求

### 16.1 问题数据

- session_id
- question_id
- prompt
- answer_type
- value_set 或 inline options
- constraints
- patient_language
- knowledge_version
- sent_at

### 16.2 回答数据

- session_id
- question_id
- answer_type
- structured_value
- display_text
- answer_state
- patient_language
- submitted_at
- client_event_id

### 16.3 不采集数据

首版不采集姓名、身份证号、手机号、住址、面部视频、声音和长期设备标识。

### 16.4 实时事件与角色隔离

P0 至少定义以下业务事件：

- question.sent
- question.cancelled
- answer.submitted
- answer.acknowledged
- answer.correction_requested
- explanation.requested
- session.snapshot
- session.ended
- locale.changed

事件必须包含 source_role 和 target_role，服务端按事件白名单强制校验和路由。患者连接不得收到危险信号、医生内部备注、规则 ID、医生修订草稿或其他仅医生可见载荷。

问题事件需要冻结问题文案、选项、语言和知识库版本快照。页面刷新或重连时通过 session.snapshot 恢复活动问题，不能只等待下一条 WebSocket 消息。

## 17. 异常与恢复

| 异常 | 患者端处理 | 数据处理 |
| --- | --- | --- |
| 无会话凭证 | 显示安全等待页 | 不请求会话内容 |
| 连接时间较长 | 提示让医生检查设备 | 保持重连 |
| 作答中断线 | 保留当前选择，锁定提交 | 本地临时保存 |
| 提交失败 | 显示“未发送成功”，提供重新发送 | 不生成重复回答 |
| 收到重复问题 | 恢复该题草稿或已提交状态 | 按 question_id 去重 |
| 收到新问题但旧题未提交 | 不静默覆盖，通知医生端存在未完成题 | 等待医生处理 |
| 会话被医生结束 | 立即进入结束页 | 清除本地临时数据 |
| 目标语言缺失 | 显示无法展示提示，请医生处理 | 不展示内部编码 |

医生删除或结束会话时，服务端应主动关闭患者现有连接并发送 session.ended，不只阻止后续重连。

## 18. 无障碍与易用性

- 文字和背景对比度达到 WCAG AA，核心问题和主要按钮优先达到更高对比度。
- 页面缩放到系统 125% 时仍不遮挡主提交按钮。
- 色觉差异用户能够通过文字、边框和图标识别选中与错误状态。
- 所有控件具有明确可访问名称和选中状态。
- 动效尊重 prefers-reduced-motion。
- 不使用闪烁、快速脉冲或持续移动吸引注意。
- 语言切换、断线提示和错误提示不造成布局跳动。

## 19. 性能与可靠性

- 本地部署下页面首次可交互目标不超过 1 秒。
- 触摸按下反馈目标不超过 100 ms。
- 本地网络正常时，提交到医生端收到事件的目标不超过 1 秒。
- 页面布局稳定，不因字体、选项或状态加载发生明显跳动。
- 1024 x 600 下页面宽高均不产生主流程滚动条。
- 重复点击提交只生成一条回答事件。

## 20. MVP 优先级

### P0：形成患者作答闭环

- 等待、连接、作答、发送、断线和结束状态。
- 单题接收和知识库驱动渲染。
- 单选、多选、数字、时长、日期或相对时间控件。
- 显式提交、发送反馈和回答回显。
- 不确定、跳过和请求解释。
- 三种语言。
- 1024 x 600 固定屏无页面滚动。
- 断线保留草稿和重连恢复。
- 会话结束清除。

### P1：提升表达能力

- 更正请求。
- 身体部位图与文字联动。
- 全屏自由文本和系统触摸键盘适配。
- 字号切换或高对比模式。
- 医生可配置的患者辅助说明。

### P2：研究与生产化探索

- 手语视频或远程翻译协助。
- 更多语言和易读版本。
- 设备级无障碍设置同步。
- 受控的患者满意度与可用性研究模块。

## 21. MVP 验收场景

### AC-P01 固定屏完整显示

在 1024 x 600 横屏下，从等待页到作答、提交和结束页均无页面级滚动，主按钮始终完整可见。

### AC-P02 单选提交

医生发送单选题，患者选择一个答案，点击确认提交，医生端收到一条结构化回答，患者端显示提交回显。

### AC-P03 多选防误触

患者可以选择、取消多个选项，选项点击不会自动发送，只有确认提交后生成回答事件。

### AC-P04 不确定性保真

患者选择“不确定”或“跳过”时，医生端收到不同状态，不得被保存为空答案。

### AC-P05 请求解释

患者点击“请医生解释”，医生端收到解释请求，患者端保持当前问题但暂时锁定回答提交。

### AC-P06 断线恢复

患者已选择但未提交时断线，页面显示断线状态；重连后同一题和选择恢复，不生成重复事件。

### AC-P07 语言切换

患者在作答中切换语言，当前选择不丢失，问题和选项切换为目标语言。

### AC-P08 风险信息隔离

无论患者答案是否触发知识库红旗条件，患者端均不展示风险结论，医生端负责人工处理。

### AC-P09 会话结束清除

医生结束会话后，患者端进入结束页；刷新或后退不能恢复问题和回答内容。

### AC-P10 触控热区

语言入口、答案选项、辅助操作和主按钮均满足最小触控热区要求，核心流程不依赖悬停和复杂手势。

## 22. 产品指标

- 单题作答完成率。
- 患者主动跳过率、不确定率和请求解释率。
- 选择后修改次数，用于发现误触或选项理解问题。
- 单题从展示到提交的用时分布。
- 提交失败率和重复提交率。
- 断线恢复成功率。
- 医生要求重发或更正的比例。
- 1024 x 600 布局溢出和滚动缺陷数。

指标只用于可用性和系统质量评估，不用于自动判断患者配合度或医疗风险。

## 23. 风险与控制

| 风险 | 控制措施 |
| --- | --- |
| 患者误触后立即发送 | 选择与提交分离，提交按钮位置固定 |
| 医学文案难理解 | 短句治理、请求解释、易读版本评审 |
| 选项太多导致一屏拥挤 | 显式分页，保留已选数量，不缩小热区 |
| 红旗提示引发患者恐慌 | 红旗只在医生端显示 |
| 系统键盘遮挡自由文本 | 全屏文本模式，P1 适配和专项测试 |
| 断线导致重复回答 | client_event_id 幂等和问题 ID 去重 |
| 语言切换造成值变化 | 存储稳定编码，界面只切换 display_text |
| 会话数据残留 | 医生结束后清除，后退不可恢复 |

## 25. 待评审决策

1. “请医生解释”是否作为 P0 固定入口，还是只在患者点击“看不懂”后出现。
2. 患者提交后是否允许在医生确认前直接撤回，还是统一采用“请求更正”。本文档暂按“请求更正”处理。
3. 自由文本是否进入 P0。本文档暂按 P1 处理，但知识库中存在 1 个自由文本问题，需要明确首版降级策略。
4. 身体部位图是否进入 P0。本文档暂按 P1，P0 使用文字选项完成同等数据采集。
5. 是否提供患者可操作的字号放大或高对比模式。
6. 会话结束页保留多长时间，以及设备如何进入下一位患者的初始状态。
7. 患者端是否展示问诊进度。若展示，应使用粗粒度阶段，不显示可能误导的精确题数。
8. 繁体医学内容是否进入 P0，以及由谁负责独立审校。

## 26. 下一轮评审重点

下一轮建议先评审以下四个问题：

1. 单题作答页的按钮层级：“确认提交”“请医生解释”“跳过”如何避免争夺注意力。
2. 选项超过 6 个时，是使用分页还是在主任务区内部有限滚动。
3. 提交后的更正机制，是患者直接撤回，还是必须由医生重发问题。
4. 繁体中文和自由文本是否进入 P0，避免范围与现有知识库能力冲突。
