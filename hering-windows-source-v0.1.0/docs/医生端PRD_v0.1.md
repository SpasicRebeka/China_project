# 医语桥医生端产品需求文档

> 版本：v0.1 评审稿，第二轮更新  
> 日期：2026-07-25  
> 状态：需求树评审中  
> 产品定义：医生引导式半结构化问诊辅助系统  
> 适用范围：成人听障患者，本地双 7 英寸触摸屏门诊研究原型

## 1. 文档目的

本文档定义医生端下一阶段的产品目标、核心流程、功能范围、业务规则、异常处理和验收标准。

本文档区分两类内容：

- 当前技术基线：已经实现的会话创建、医生与患者双端连接、角色令牌、WebSocket 通道和本地会话存储。
- 目标产品能力：医生选择问诊方向、向患者发送问题、接收结构化回答、人工复核危险信号，并形成可编辑的现病史草稿。

## 2. 背景与问题

听障患者在门诊中面临的核心障碍，是患者身体体验、手语或文字表达与医学问诊语言之间存在转换成本。医生需要在有限时间内识别信息缺口、组织追问并记录病历，容易出现重复沟通、遗漏和记录负担。

医生端需要把医生隐性的问诊逻辑变成可操作的节点，同时保留医生对问题选择、临床判断和最终病历内容的控制权。

## 3. 产品目标

### 3.1 总目标

帮助医生在不让系统代替诊断的前提下，与听障患者完成一轮可理解、可追溯、可人工修订的半结构化问诊。

### 3.2 一级产品目标

1. 快速进入问诊：医生能够创建会话、确认患者端已连接并选择当前主诉。
2. 有序完成追问：系统提供基于主诉的有限问题集合，医生决定向患者发送哪些问题。
3. 准确接收信息：患者回答实时回传，并保留回答状态、来源和不确定性。
4. 优先处理风险：危险信号只在医生端显示，要求医生进行人工临床评估。
5. 减轻记录负担：将已确认回答映射为可编辑的现病史草稿，由医生最终确认。

### 3.3 非目标

首版不提供以下能力：

- 自动诊断或疾病概率排序
- 鉴别诊断结论
- 检查、用药或治疗建议
- 自动分诊或急诊去向建议
- 替代医生进行危险信号处置
- 与医院 HIS、EMR 或电子签名系统直接集成
- 儿童、妊娠专病、创伤或精神科危机问诊路径
- 自动手语识别或自动语音识别
- 长期患者档案和跨次就诊历史

## 4. 用户与使用环境

### 4.1 核心用户

| 用户 | 目标 | 主要痛点 |
| --- | --- | --- |
| 接诊医生 | 快速获得完整、可信的现病史信息 | 沟通耗时、信息遗漏、记录负担 |
| 听障患者 | 理解医生的问题并准确表达身体体验 | 医学术语难懂、表达形式不匹配、回答压力 |

### 4.2 相关角色

- 医疗安全审核人：审核危险信号条件与医生端提示文案。
- 知识库维护者：维护问题、选项、字段映射、证据来源和版本。
- 设备或运维人员：维护本地双屏终端、浏览器 kiosk 和离线部署。

### 4.3 典型环境

- 医生与患者在同一诊室。
- 医生端和患者端分别运行在独立的 7 英寸触摸屏或终端。
- 页面全部通过触摸操作，不以鼠标、悬停或物理键盘作为完成主流程的前提。
- 服务默认只在本机运行，不依赖外部网络。
- 医生掌握会话创建、结束和数据清除权限。
- 患者端仅显示当前问题、可理解的回答选项和必要的交互反馈。

## 5. 产品原则

1. 医生主导：系统推荐问题，医生决定是否发送。
2. 患者可理解：患者端不出现疾病名称、鉴别诊断或风险结论。
3. 不确定性保真：不确定、无法表达、跳过必须作为正式回答状态保留。
4. 风险提醒不等于诊断：危险信号只触发医生优先人工复核。
5. 一次只完成一个沟通任务：患者端一屏一问，避免同时展示多个医学问题。
6. 可追溯：病历草稿中的每个结构化片段能够追溯到患者回答或医生修订。
7. 数据最小化：研究原型默认不采集姓名、身份证号、联系方式等直接身份信息。
8. 本地优先：断开外网不影响核心问诊闭环。

## 6. 首版范围

### 6.1 人群范围

- 年龄：18 岁及以上成人。
- 沟通对象：聋人及不同程度听力障碍患者。
- 本版不根据听力障碍类型自动推断沟通方式，由医生和患者共同选择文字、图形或其他辅助方式。
- 研究原型只记录临时患者编号、年龄和性别，不采集姓名、身份证号、手机号、住址或其他直接身份信息。

### 6.2 主诉范围

首版使用现有知识库中的 7 个主诉入口：

P0 中每个会话只能选择一个主诉。需要处理另一主诉时，医生结束当前会话并创建新会话。单次会话多主诉能力放入 P1。

| 主诉 | 基础问题数 | 伴随症状数 | 危险信号规则数 |
| --- | ---: | ---: | ---: |
| 胸痛 | 6 | 6 | 4 |
| 胸闷 | 5 | 6 | 3 |
| 咳嗽 | 6 | 7 | 3 |
| 发热 | 8 | 8 | 5 |
| 腹痛 | 9 | 8 | 5 |
| 头晕 | 6 | 6 | 5 |
| 乏力 | 8 | 7 | 5 |

以上数量来自知识库 v0.1.0，仅用于定义原型范围，不代表诊疗路径完整性。

## 7. 核心使用流程

### 7.1 主流程

```text
医生打开终端
  -> 系统创建临时会话
  -> 医生确认患者端已连接
  -> 医生选择主诉
  -> 系统加载结构化追问
  -> 医生选择并发送一个问题
  -> 患者端展示通俗问题与选项
  -> 患者提交回答
  -> 医生端实时显示回答
  -> 系统更新问诊完成度和病历草稿
  -> 必要时提示医生优先人工复核
  -> 医生继续追问、修订或补充记录
  -> 医生确认草稿并复制或导出
  -> 医生结束会话并清除临时数据
```

### 7.2 会话状态

```text
创建中 -> 等待患者 -> 已连接 -> 问诊中 -> 待确认 -> 已结束
   |          |          |         |
   +------ 失败或断开，可重试或恢复 ------+
```

### 7.3 问题状态

- 未发送
- 已加入待问列表
- 已发送，等待回答
- 已回答，待医生确认
- 已确认
- 医生跳过
- 患者跳过
- 需要医生补充确认

## 8. 信息架构

### 8.1 页面总体布局

医生端采用“左侧主工作区，右侧双层信息栏”的桌面布局：

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 全局状态栏：会话 / 患者连接 / 语言 / 结束会话                      │
├──────────────────────────────────────────────┬──────────────────────┤
│                                              │ 实时回答区           │
│                                              │ 当前回答 / 历史回答  │
│  系统索引     问诊知识图谱工作区             │ 待确认 / 断线状态    │
│                                              ├──────────────────────┤
│       主诉 / 问题 / 伴随症状 / 一级追问      │ 临床记录区           │
│                                              │ 风险提醒 / 结构化字段│
│                                              │ 现病史草稿           │
└──────────────────────────────────────────────┴──────────────────────┘
```

- 基准分辨率为横屏 1024 x 600，问诊工作区占约 680 px 宽度。
- 右侧信息栏占约 344 px 宽度，内部采用上下两行布局。
- 右侧上方实时回答区建议约 232 px 高，下方临床记录区建议约 296 px 高，中间保留约 8 px 的视觉分隔。
- 右侧使用固定比例，不要求医生拖动细小分隔线。
- 点击右侧任一区域可进入临时放大视图，再通过明确的返回按钮回到图谱工作台。
- 全局状态栏保持单行，不侵占知识图谱主要操作空间。
- 主诉快捷索引可作为知识图谱左侧的窄栏或可收起面板，不单独形成大面积区域。

### 8.2 问诊知识图谱工作区

问诊工作区采用类似知识笔记软件的空间化知识图谱形式。它是可操作的问诊导航画布，不是疾病知识图谱，也不承担自动推理。

#### 节点类型

1. 主诉节点：当前图谱的中心节点，P0 每个会话只有一个。
2. 症状属性节点：部位、性质、起病时间、持续时间、频率、程度、诱因、缓解因素和发展变化。
3. 伴随症状节点：知识库中需要逐项确认的有限伴随症状。
4. 问题节点：医生可以预览并发送给患者的具体问题。
5. 一级补充追问节点：伴随症状回答为“有”后才展开。

图谱不采用传统树状菜单或四组折叠卡片作为主要结构，而采用“全局神经网络 + 焦点子图”：

- 全局网络以 7 个系统分类作为枢纽节点，主诉节点分布在系统之间。
- 同一主诉可以连接多个系统枢纽，体现问诊导航上的交叉关系。
- 点击主诉后，该主诉成为焦点节点，直接相邻的症状属性、伴随症状和问题节点进入前景。
- 距离焦点较远的网络保持淡化可见，帮助医生保留整体空间位置和返回路径。
- 点击相邻节点后继续展开局部子图，不把整个网络替换成新的页面。

#### 连线语义

- 主诉 -> 需要询问 -> 症状属性
- 主诉 -> 可能伴随 -> 伴随症状
- 属性或症状 -> 通过问题采集 -> 问题
- 患者回答 -> 触发 -> 一级补充追问
- 已确认回答 -> 映射到 -> 病历字段

“可能伴随”只代表需要向患者确认的问诊关系，不表示因果、疾病方向或诊断概率。

#### 节点状态

每个节点同时使用图形、文字和颜色表示状态，不得只依赖颜色：

- 未询问
- 已加入待问列表
- 已发送，等待患者回答
- 患者已回答，待医生确认
- 医生已确认
- 不确定或无法表达
- 需要医生优先确认
- 已跳过

#### 核心操作

- 单指平移、双指缩放和一键回到主诉中心。
- 必须同时提供清晰的放大、缩小和回到中心按钮，不能强制医生使用双指手势。
- 点击节点将其设为焦点，并查看患者端问题预览、回答选项和病历字段。
- 从问题节点直接发送问题或加入待问列表。
- 患者回答后，相关节点和右侧实时回答区同步更新。
- 医生确认回答后，节点状态和右下临床记录区同步更新。
- 伴随症状回答为“有”时，只展开一级补充追问。
- 支持按“全部、未询问、待确认、已确认、需优先确认”过滤节点。
- 提供稳定布局，已显示节点不得因新回答发生大幅跳动。
- 前景同时保留约 6 至 10 个可操作节点；更远节点以淡化背景节点存在，进入邻近焦点后才变成可操作节点。
- 不设置只能通过悬停发现的按钮、说明或状态。
- 图谱首次载入时允许短暂、轻微的力导向展开动画，稳定后锁定节点位置。
- 医生不能自由拖动单个节点改变知识结构，但可以平移整个画布。
- 聚焦新节点时只调整局部邻居，禁止整张图重新随机排列。
- 当前焦点节点保持在画布视觉中心或中心偏左位置，下一步可操作节点围绕焦点排列。
- 患者回答并经医生确认后，对应节点和有效路径逐步点亮；未处理节点保持中性。

### 8.3 实时回答区

- 固定在右侧上方，优先显示患者最新回答。
- 展示当前问题、原始回答、回答时间、语言和回答状态。
- 展示待医生确认的回答队列和最近回答历史。
- 患者断线、超时或修改回答时，在此区域提供明确状态。
- 医生可在该区域完成确认、修订、补问或标记待处理。

### 8.4 临床记录区

- 固定在右侧下方。
- 顶部优先显示尚未查看的危险信号提醒。
- 中部显示当前已确认的结构化字段。
- 下部显示可编辑的现病史草稿，并提供确认与复制操作。
- 草稿编辑区不得因新回答自动滚动或覆盖医生正在编辑的内容。

### 8.5 视觉优先级

当前问题、患者最新回答和未处理风险具有最高视觉优先级。页面不应把所有节点和右侧内容做成同等权重的卡片，也不应通过动画持续抢夺医生注意力。

### 8.6 7 英寸纯触控约束

- P0 基准设备锁定为 7 英寸、1024 x 600 横屏触摸屏。
- 页面不产生整体横向滚动，核心操作在 1024 x 600 视口内可达。
- 顶部全局状态栏高度建议为 60 至 64 px，主体可用高度约 536 至 540 px。
- 左侧图谱工作区建议约 680 px，右侧信息栏建议约 344 px，分隔线计入右侧宽度。
- 主要触控目标不小于约 60 x 60 px，主操作按钮高度建议为 64 至 72 px。
- 60 px 是针对该 7 英寸设备的原型基准；硬件到位后仍需用实体屏幕复核实际物理尺寸和误触率。
- 相邻触控目标之间保留足够间距，避免误触。
- 节点文字最多显示两行，长问题点击后在右侧回答区或放大视图中完整展示。
- 不使用右键、悬停、滚轮、鼠标拖拽或键盘快捷键作为必需操作。
- 长按只能作为辅助快捷操作，不得承载唯一功能。
- 删除、结束会话、覆盖未回答问题等高风险操作必须使用大尺寸确认控件。
- 图谱缩放后仍需保证当前问题、最新回答和风险提醒可通过固定入口返回。
- 输入自由文本时使用屏幕键盘，并避免让输入框被软键盘遮挡。

### 8.7 主诉快捷索引

主诉快捷索引位于问诊工作区左侧，采用“系统分类 -> 相关症状”的两级结构。它是全局图谱的辅助定位工具，不是唯一入口，也不表示疾病归属或诊断方向。

#### 一级系统分类

- 心血管系统
- 呼吸系统
- 消化系统
- 神经系统
- 内分泌系统
- 泌尿系统
- 血液系统

#### 二级相关症状

- 医生点击系统分类后，图谱自动聚焦该系统枢纽，并突出其相关症状。
- 同一症状可以出现在多个系统分类中，例如胸闷可以同时作为心血管和呼吸方向的问诊入口。
- 症状与系统的关系只用于导航，不显示疾病名称、疾病概率或诊断结论。
- P0 中仅胸痛、胸闷、咳嗽、发热、腹痛、头晕和乏力可以启动完整问诊。
- 尚未配置完整模板的症状可以作为关联症状展示，但必须明确标记“暂不支持作为主诉开始问诊”。
- 系统分类和症状映射在真实临床使用前必须经过本地临床审核。

#### P0 系统与症状映射草案

下表根据现有知识库 v0.1.0 的 7 个主诉和伴随症状整理，只定义产品导航关系。症状允许跨系统重复出现，不表示唯一医学归属。

| 系统分类 | P0 可启动主诉 | 关联展示症状，P0 不可直接启动 |
| --- | --- | --- |
| 心血管系统 | 胸痛、胸闷、头晕、乏力 | 心慌或心跳不齐、气短、明显出汗、眼前发黑或晕倒 |
| 呼吸系统 | 咳嗽、胸闷、胸痛、发热 | 气短或喘不过气、喘鸣、咳血、鼻塞或流涕、咽部不适 |
| 消化系统 | 腹痛、发热 | 恶心或呕吐、腹泻、便秘或停止排便排气、反酸或烧心、呕血、黑便或便血、黄疸 |
| 神经系统 | 头晕、乏力、发热 | 单侧无力或麻木、视物异常、说话或吞咽困难、剧烈头痛、颈部疼痛或僵硬、晕倒、意识状态变化 |
| 内分泌系统 | 乏力 | 体重明显变化、夜间出汗、睡眠后仍不解乏、白天明显困倦 |
| 泌尿系统 | 发热、腹痛 | 尿痛、尿频、血尿、腰背一侧疼痛 |
| 血液系统 | 乏力、头晕、发热 | 异常出血、黑便、月经过多、体重下降、夜间出汗、心慌或晕厥 |

映射约束：

- P0 可启动主诉必须统一指向知识库中的现有 7 个主诉 ID。
- 关联展示症状来自现有主诉的伴随症状集合，点击后只显示其与当前主诉的关系，不启动新的完整问诊。
- 表中“体重明显变化”等概括性标签在实现前需要拆回知识库已有的准确患者文案，不能直接替换经过审校的问题。
- 医学表达、系统归类和交叉入口需要由本地内科及医疗安全审核人确认后才能用于真实临床场景。

#### 7 英寸触控交互

- 主诉选择阶段，系统分类使用约 80 至 88 px 宽的固定触控栏，并计入 680 px 问诊工作区。
- 每个系统入口使用大尺寸图标加短标签，触控高度不小于 60 px。
- 点击系统后优先通过图谱聚焦展示相关症状；只有节点过多时才使用覆盖式症状列表。
- 症状项使用单列大按钮或最多两列的大按钮布局，禁止密集小标签云。
- 选择症状后显示主诉确认页；确认后索引自动收起并进入对应知识图谱。
- 进入问诊后，索引收起为约 56 至 64 px 的系统入口按钮，释放图谱空间。
- 已进入问诊后仍可点开索引查看，但 P0 不允许在当前会话中切换主诉。

### 8.8 基于平面设计准则的页面逻辑

页面不在所有阶段同时展示全部模块内容，而是根据医生当前任务改变视觉主次。整体采用“一个主任务、一个反馈区、一个记录区”的层级。

#### 状态一：等待患者连接

- 主视觉：患者连接状态和患者端入口。
- 图谱区域暂不展示复杂节点，只显示主诉索引入口和开始提示。
- 右上显示连接步骤和设备状态。
- 右下显示临时患者编号、年龄和性别录入。
- 患者未连接前，发送问题按钮不可用，并说明不可用原因。

#### 状态二：选择主诉

- 主视觉：由 7 个系统枢纽和 P0 主诉组成的全局网络。
- 医生可以直接点击图谱中的主诉，也可以用左侧系统索引快速聚焦。
- 右上显示患者已连接状态和当前沟通语言。
- 右下显示即将创建的现病史草稿范围，不显示空白大文本框。
- 点击症状后先进入大尺寸确认页，确认后才生成图谱，避免误触直接开始问诊。

#### 状态三：进行问诊

- 主视觉：以当前主诉或当前问题为中心的焦点子图，背景仍保留淡化的全局网络。
- 系统索引收起，仅保留可再次打开的入口。
- 右上始终显示最新患者回答，并提供确认、修订和补问操作。
- 右下只显示危险信号摘要、已确认字段摘要和草稿预览，不在狭窄区域完成长文本编辑。
- 点击右下草稿区进入全屏记录模式。

#### 状态四：需要优先人工确认

- 未处理危险信号出现时，右下区域的顶部固定显示提醒。
- 图谱对应节点增加文字状态和警示图标，但不把整个画布染成红色。
- 红色只用于未处理的高优先级提醒，已查看后转为中性留痕状态。
- 提醒不得遮挡当前患者回答，也不得自动跳转或抢走医生正在编辑的输入焦点。

#### 状态五：复核现病史草稿

- 点击临床记录区后进入全屏记录模式，暂时隐藏知识图谱和实时回答区。
- 顶部保留返回问诊、会话状态和未处理风险数量。
- 主区域展示结构化字段与可编辑草稿。
- 底部固定显示“返回问诊”和“确认并复制”两个大尺寸操作。
- 返回工作台后恢复原有图谱位置和展开状态。

#### 状态六：结束会话

- 先检查是否存在未确认回答、未查看提醒或未复制草稿。
- 用全屏确认页代替小弹窗，明确展示即将清除的内容。
- 结束后进入完成页，不立即自动创建下一会话，防止误操作。

### 8.9 视觉组织规则

#### 层级

1. 一级信息：当前问题、患者最新回答、未处理危险信号。
2. 二级信息：下一步节点、待确认回答、已确认字段摘要。
3. 三级信息：来源、时间、知识库版本、历史记录和辅助说明。

三级信息默认折叠，避免与临床任务竞争注意力。

#### 格式塔分组

- 接近原则：问题与对应回答保持空间邻近。
- 相似原则：相同节点类型使用一致的尺寸、图标位置和边框规则。
- 连续原则：连线只表达问诊顺序和字段映射，避免装饰性连线。
- 共同区域：实时回答和临床记录用明确容器分区，不使用大量漂浮卡片。

#### 色彩与形状

- 页面使用一个主强调色表示当前选中或当前进行中。
- 中性色表示未开始或普通历史状态。
- 琥珀色表示待确认，红色只表示未处理的危险信号。
- 已确认状态使用图标和文字共同表达，不只依赖绿色。
- 节点统一使用中等圆角矩形，避免不同形状过多导致视觉噪声。

#### 字体与信息密度

- 全局主要正文不小于 16 px。
- 图谱节点标签建议 16 至 18 px，最多两行。
- 当前问题和最新回答建议 18 至 20 px。
- 面板标题建议 18 px，页面主标题建议 22 至 24 px。
- 时间、来源等辅助信息可使用 13 至 14 px，但不得承载关键操作或风险内容。

#### 触控反馈

- 按下时提供明显的背景、边框或位移反馈。
- 发送问题后立即进入“发送中”状态，成功或失败必须可见。
- 不使用双击作为必需操作。
- 不使用需要精确瞄准的节点端口、细线按钮或小型关闭图标。

## 9. 功能需求

### 9.1 会话与连接

#### DR-S01 创建会话，P0

- 医生打开医生端后，系统自动创建临时会话。
- 系统生成医生令牌和患者令牌，角色权限必须隔离。
- 医生端显示短会话编号，不展示完整令牌。
- 创建失败时提供明确重试操作。

验收标准：

- 创建成功后，医生端进入“等待患者”状态并生成患者端入口。
- 创建失败时，页面不能停留在无限加载状态。

#### DR-S02 患者连接确认，P0

- 医生端实时显示患者端未连接、已连接、暂时断开和会话失效状态。
- 状态不能只用颜色表达，必须同时有文字和图标。
- 患者连接后，医生才能发送问题。

#### DR-S03 断线恢复，P0

- 患者端短暂断开时，医生端保留已确认回答和当前进度。
- 同一有效患者令牌重新连接后恢复当前问题。
- 会话过期时禁止继续发送问题，并引导医生创建新会话。

#### DR-S04 结束与清除，P0

- 只有医生端可以结束和清除会话。
- 清除前需要二次确认，并提示未复制的病历草稿将无法恢复。
- 完成清除后，患者端令牌立即失效。

### 9.2 主诉与问诊导航

#### DR-N01 主诉快捷入口，P0

- 第一级展示心血管、呼吸、消化、神经、内分泌、泌尿和血液系统分类。
- 点击系统分类后展示其下属相关症状。
- 胸痛、胸闷、咳嗽、发热、腹痛、头晕和乏力作为 P0 可启动完整问诊的主诉。
- 同一症状允许出现在多个系统下，但所有入口必须指向同一个症状 ID和问诊模板。
- 医生选择主诉后加载对应问题、伴随症状和危险信号条件。
- P0 中主诉一经确认不可在当前会话内替换，避免不同主诉的字段和规则互相污染。
- 系统不得因为主诉选择而显示疾病名称。

#### DR-N02 切换或增加主诉，P1

- 医生可以在问诊过程中增加第二主诉。
- 切换主诉前保留已确认回答。
- 多主诉的病历草稿必须分别组织，避免字段互相覆盖。

#### DR-N03 问诊进度，P0

- 分别显示未问、等待回答、待确认和已确认数量。
- 进度只表示信息采集状态，不表示诊断完成度或安全程度。

### 9.3 问题选择与发送

#### DR-Q01 查看推荐问题，P0

- 按知识库 `question_sequence` 在知识图谱中组织推荐顺序。
- 每个问题显示医生术语、患者端预览、回答类型和病历字段。
- 医生可以查看问题来源，但首屏默认不展开证据详情。
- 医生点击图谱节点后查看详情，不要求在画布中直接展示全部长文本。

#### DR-Q02 发送单个问题，P0

- 医生每次只向患者端发送一个问题。
- 发送前能够预览患者实际看到的语言和选项。
- 患者存在未回答问题时，再次发送必须明确替换或取消原问题。

#### DR-Q03 待问列表，P1

- 医生可以提前选择若干问题形成待问列表。
- 系统仍按一屏一问发送，不得一次推送多个问题。
- 医生可以调整顺序、删除和跳过。

#### DR-Q04 伴随症状追问，P0

- 伴随症状先采集“有、无、不确定、无法表达”。
- 仅当患者回答“有”时，展开一级必要追问。
- 系统不得无限递归扩展伴随症状。

#### DR-Q05 医生自定义文字问题，P1

- 医生可发送临时自由文本问题。
- 自定义问题必须标记为“医生补充”，不自动映射到标准病历字段。
- 自定义问题仍需保留原始问题与患者回答。

### 9.4 患者回答处理

#### DR-R01 实时接收回答，P0

- 医生端收到患者回答后立即显示，不覆盖历史回答。
- 回答记录包含问题、答案、语言、时间和来源角色。
- 患者修改答案时保留最新值，并记录发生过修改。

#### DR-R02 医生确认，P0

- 患者回答默认处于“待医生确认”。
- 医生确认后才能进入最终病历草稿。
- 对“不确定、无法表达、跳过”的回答，系统提示医生决定是否人工补问。

#### DR-R03 医生修订，P0

- 医生可以修订结构化值或补充自由文本。
- 修订后同时保留患者原始回答和医生最终记录。
- 界面应明确区分“患者回答”和“医生修订”。

### 9.5 危险信号提醒

#### DR-A01 触发提醒，P0

- 当已收到的回答满足知识库条件时，只在医生端显示提醒。
- 统一提示文案为：“发现需要医生优先确认的信息，请立即进行人工临床评估。”
- 提醒不得显示疾病推断、概率、治疗或去向建议。

#### DR-A02 人工确认，P0

- 提醒在医生处理前保持可见，不得自动消失。
- 医生可标记“已查看，继续人工评估”。
- 原型只记录确认状态，不要求医生填写诊断或处置结果。

#### DR-A03 规则治理，P0

- 每次触发保留规则 ID、知识库版本、触发字段和时间。
- 任何危险信号规则更新必须记录审校人、日期和变更理由。
- 上线到真实临床环境前，规则和文案必须经过本地临床与医疗安全审核。

### 9.6 现病史草稿

#### DR-M01 自动组织草稿，P0

- 按知识库 `documentation_order` 组织已确认字段。
- 草稿患者信息区只使用临时编号、年龄和性别，不出现姓名或其他直接身份信息。
- 草稿至少包含主诉、起病时间、部位、性质、持续时间、频率、严重程度、诱发因素、缓解因素、发展变化和伴随症状中的已采集项。
- 未采集字段不得被系统臆测或补全。
- 不确定内容必须明确写为“不确定”或“患者无法表达”，不能改写成确定陈述。

#### DR-M02 可编辑与可追溯，P0

- 医生可以直接编辑草稿。
- 结构化字段更新时，草稿对应片段同步更新。
- 医生进行自由文本修改后，不得被后续自动刷新静默覆盖。

#### DR-M03 确认与复制，P0

- 医生确认后可复制纯文本草稿。
- 复制内容不包含会话令牌、内部规则 ID或调试信息。
- 原型不得宣称已写入正式电子病历。

#### DR-M04 导出，P2

- 后续可支持受控 JSON 或文档导出。
- 在明确医院接口、身份认证、审计和合规要求前，不接入正式 EMR。

### 9.7 语言与沟通辅助

#### DR-L01 患者语言选择，P0

- 支持简体中文、繁体中文和英文基础界面。
- 医生端始终能预览患者端当前显示语言。
- 切换语言不能清空已回答内容。

#### DR-L02 非声音反馈，P0

- 所有连接、发送、接收、错误和风险状态必须有可见反馈。
- 不得用提示音作为唯一反馈方式。

## 10. 关键业务规则

1. 医生是唯一可以创建、结束和清除会话的角色。
2. 患者端不能查看危险信号、疾病名称、鉴别诊断或医生内部备注。
3. 系统不能自动发送下一问题，除非医生明确启动预先审核过的顺序模式。首版不启用该模式。
4. 同一时刻患者端最多存在一个待回答问题。
5. 只有医生确认的回答进入最终草稿。
6. 患者原始回答不得因医生修订而丢失。
7. 危险信号提醒不能被普通“关闭”操作永久隐藏，只能标记已查看。
8. 知识库缺少字段时，系统显示“未采集”，不得生成看似完整的内容。
9. 头晕路径以时间和诱因为主要组织方式，感觉性质只用于记录。
10. 与听力相关的危险信息必须明确比较“与平时相比是否新出现或明显加重”。
11. P0 中一个会话只对应一个主诉，多主诉必须分别建立会话。
12. 研究原型只允许临时编号、年龄和性别进入患者信息区，不提供姓名、证件号、手机号或住址输入字段。

## 11. 数据需求

### 11.1 会话级数据

- 会话 ID
- 临时患者编号、年龄和性别
- 创建时间、过期时间和结束时间
- 医生端与患者端连接状态
- 患者显示语言
- 当前主诉和当前问题
- 知识库版本

### 11.2 问答记录

- 问题 ID、字段 ID和主诉 ID
- 医生发送时间、患者回答时间
- 原始回答、标准化值和回答状态
- 患者原始语言
- 医生确认、修订或跳过状态
- 来源角色和事件 ID

### 11.3 草稿记录

- 结构化现病史字段
- 自动生成草稿
- 医生自由文本修订
- 确认状态和复制时间

### 11.4 风险提醒记录

- 规则 ID和知识库版本
- 触发字段
- 触发时间
- 医生查看状态与查看时间

## 12. 权限、隐私与安全

- 服务默认监听 `127.0.0.1`，核心流程不调用外部服务。
- 使用短期、分角色令牌，患者令牌不能执行医生操作。
- 默认不采集患者姓名、证件号、手机号和住址。
- 年龄和性别仅用于本次问诊草稿，由医生录入并在复制前确认。
- 会话结束后，由医生执行本地清除。
- 日志不得记录完整令牌、完整患者自由文本或可直接识别身份的信息。
- 生产化前需要单独完成医院信息安全、数据保护、医疗器械属性和临床使用边界评估。本 PRD 不构成合规结论。

## 13. 无障碍与易用性

- 以 WCAG 2.2 AA 作为 Web 端基础验收参考。
- 所有主流程操作必须可以只通过触摸完成；同时保留键盘焦点和语义结构，便于测试及辅助技术兼容。
- 知识图谱必须提供等价的树状列表视图，使用户不依赖平移、缩放或拖动画布也能完成全部问诊操作。
- 触控目标按 7 英寸设备的实际物理尺寸验收，不只按 CSS 像素验收。
- 颜色不能作为唯一信息载体。
- 医学问题使用短句、主动语态，避免否定嵌套和不必要术语。
- 患者端保持一屏一问，医生端同时提供患者屏幕预览。
- 正文缩放到 200% 时不得丢失功能或关键信息。
- 所有图形表达必须同时提供文字标签和可访问名称。

## 14. 性能与可靠性

- 本地网络正常时，问题发送和回答回传应呈现近实时反馈。
- 所有发送动作必须有发送中、成功或失败状态，禁止静默失败。
- 重复事件根据 `event_id` 去重，避免同一回答重复写入草稿。
- 断线重连不得覆盖已经确认的数据。
- 页面刷新后，在令牌仍有效时能够恢复当前会话。
- 静态资源、知识库和基础问诊功能必须支持离线运行。

## 15. MVP 优先级

### P0：形成可演示闭环

- 自动创建会话与患者连接确认
- 7 个主诉入口
- 推荐问题序列
- 单问题发送与患者实时回答
- 医生确认与修订
- 一级伴随症状追问
- 医生端危险信号提醒与人工查看状态
- 可编辑现病史草稿
- 医生确认后复制现病史草稿，作为 MVP 的正式终点
- 断线恢复、错误状态和会话清除
- 简体中文、繁体中文和英文基础支持

### P1：提升医生效率

- 待问列表和顺序调整
- 第二主诉
- 医生自定义文字问题
- 问题搜索和来源查看
- 更细的问诊完成度
- 会话内操作记录查看

### P2：生产化探索

- 受控文档或结构化数据导出
- 医院系统集成
- 经验证的 ASR 或字幕能力
- 更丰富的患者视觉表达素材
- 知识库后台与临床审校工作流

## 16. MVP 验收场景

### AC-01 完成基础问诊

给定医生端和患者端均已连接，当医生选择“胸闷”并发送问题，患者提交回答后，医生端应显示原始回答并允许确认，确认后对应字段进入现病史草稿。

### AC-02 保留不确定性

给定患者选择“不确定”或“无法表达”，当医生查看回答和草稿时，系统必须保留该状态，不得自动改写为“无”。

### AC-03 危险信号仅医生可见

给定回答满足危险信号条件，当规则触发时，医生端显示人工评估提醒，患者端不显示疾病、风险等级或处置建议。

### AC-04 医生修订可追溯

给定患者已提交回答，当医生修订结构化值时，系统同时保留患者原始回答和医生修订值，草稿采用医生确认后的值。

### AC-05 断线恢复

给定问诊已完成若干问题，当患者端短暂断开并使用有效令牌重连时，已确认回答和当前问题不得丢失。

### AC-06 权限隔离

给定患者令牌，当患者端尝试结束或清除会话时，请求必须被拒绝，界面也不显示该操作。

### AC-07 清除确认

给定草稿尚未复制，当医生点击结束并清除时，系统必须提示数据不可恢复，并要求二次确认。

## 17. 产品指标

研究原型阶段先采集基线，不预设临床效果结论：

- 从创建会话到患者成功连接的用时
- 单个问题从发送到回答的用时
- 每次问诊的已确认字段覆盖率
- “不确定、无法表达、跳过”的比例
- 医生对自动草稿的修订次数和修订类型
- 危险信号提醒的查看时延
- 断线、重试和会话失败次数
- 医生完成任务所需点击数与主观可用性反馈
- 患者对问题理解度和表达负担的反馈

这些指标用于评估沟通效率和产品可用性，不用于证明诊断准确性。

## 18. 风险与控制

| 风险 | 影响 | 首版控制 |
| --- | --- | --- |
| 医生误以为系统给出诊断 | 临床判断偏移 | 全局标注辅助定位，禁止疾病结论和概率 |
| 危险信号漏报或误报 | 延误评估或告警疲劳 | 只作人工复核触发器，规则经本地临床审校 |
| 患者误解问题 | 回答失真 | 通俗短句、一屏一问、允许不确定与无法表达 |
| 自动草稿产生错误确定性 | 病历内容失真 | 只使用已确认字段，保留缺失和不确定状态 |
| 双端断线 | 问诊中断 | 可见状态、重连恢复、发送确认和事件去重 |
| 临时数据泄露 | 隐私风险 | 本地运行、短期令牌、最小化采集、医生清除 |
| 知识库版本失控 | 问题与规则不可追溯 | 每次会话固定知识库版本，规则变更留痕 |

## 19. 当前实现差距

- 危险信号触发与人工确认
- 现病史草稿生成和复制
- 会话恢复与产品级异常处理

## 20. 产品决策记录

### 20.1 已确认

- 2026-07-25：MVP 的最终产物为医生可编辑、确认并复制的现病史草稿，不停留在结构化字段或演示摘要。
- 2026-07-25：P0 严格采用一个会话对应一个主诉；单次会话多主诉能力放入 P1。
- 2026-07-25：研究原型不采集直接身份信息，只记录临时编号、年龄和性别，并随会话清除。
- 2026-07-25：医生端采用左侧大比例问诊知识图谱工作区；右侧上方为实时回答区，右侧下方为临床记录区。
- 2026-07-25：医生端和患者端均按 7 英寸纯触控终端设计，P0 不依赖鼠标、悬停或物理键盘。
- 2026-07-25：医生端基准设备分辨率锁定为 1024 x 600 横屏。
- 2026-07-25：主诉快捷索引采用系统分类与相关症状两级结构，系统关系只用于问诊导航。
- 2026-07-25：页面按连接、主诉选择、问诊、风险复核、草稿复核和结束六种任务状态调整视觉主次；长文本草稿使用全屏复核模式。
- 2026-07-25：问诊图谱采用类似关系笔记软件的“全局神经网络 + 焦点子图”形式；首次展开后锁定位置，聚焦时只调整局部邻居。

### 20.2 待决策

1. 医生修订患者回答时，是否需要填写修订原因？
